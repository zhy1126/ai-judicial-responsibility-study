# 模拟裁判说明配音接入

本次不需要在网页中配置配音服务TOKEN。先用文字生成固定音频，再把录音作为静态文件部署；这样所有参与者听到同一个版本。

## 待配音文字

`audio/scripts/` 内有八份带说话人标记的对话TXT。natural为故意伤害案，statutory为侵犯著作权案；none、procedural、substantive、decisional分别对应无AI、程序性、实质性、决定性参与。

这是新的对话稿（dialogue-2026-09-08-v1），替代此前单一法官朗读稿。每份含13条消息：法官与AI交替问答并由法官最终签署；无AI条件对应法官与书记员。

`audio/dialogue-manifest.json` 提供八个录音的104个片段，逐条列明role、speaker、stage、text。文字来自网站同一个对话模块，可用 `node scripts/export-dialogue-audio.mjs` 重新导出，避免网页与配音不一致。

## 制作与核对

按说话人分别生成每条text，再依次拼接成对应情境的一条录音。TXT中的【序号·说话人·阶段】是制作标记，不需朗读；使用JSON可直接提取text。

法官使用固定音色；AI回复使用另一固定音色。无AI条件的回复属于书记员，不能朗读成AI或添加AI名称。尽量统一各条件的语速、响度和段间停顿，避免音乐、情绪效果及模仿真实法官。

逐条核对“八万九千九百八十四元”“有期徒刑十五年”“剥夺政治权利三年”“有期徒刑八个月”“罚金人民币九万元”。不要让配音服务自动总结、增删或重写。实际时长由音频文件确定，不虚构已生成录音。

## 文件与配置

将八个MP3文件放入 `audio/recordings/`，建议使用清单中的文件名，例如 `natural-none-dialogue-v1.mp3`。修改 `audio-config.js`，将对应空字符串改为同源相对地址 `./audio/recordings/natural-none-dialogue-v1.mp3`，其余类推。`STUDY_AUDIO_VERSION` 必须与对话清单version一致。不要把旧独白录音配到新对话上。

所有八条地址都配置完整且版本匹配后才统一切换纯音频播放器，避免只有部分实验条件能够收听。四种条件共用同一段合成配音来源说明，不显示文字、字幕或可展开的文字记录。未补齐前各条件统一使用 chatbot 对话框，消息逐字输出并保留历史气泡，可向上回看。

网页不会自动播放；支持暂停、继续和从头播放，没有快进控制。完整播放后才能勾选确认并进入裁判结果。音频加载失败时显示重试并暂停下一步，不自动回退文字；因此配置前务必核对全部八条可用。刷新后恢复播放位置并保持暂停，离开播放页或隐藏标签页时暂停。

运行 `node scripts/build.mjs` 确认录音被复制到 `_site/audio/recordings/`。部署后分别验证八条录音可播放，文字一致、正确对应条件、无破音与明显响度差异。记录提供方、音色与生成参数，后续不要在同一采集版本中途换音色。

## 最后开放题的语音识别

此功能与配音独立。当前使用浏览器可用的中文SpeechRecognition；参与者主动点击才申请麦克风。停止后等待最终识别，5秒未收到结束事件则中断并回到手动输入，迟到片段不会写入答案。

浏览器可能向其语音服务发送音频，页面已说明这一点；应用不保存原始音频，只保存参与者确认文字及不含音频的输入方式／错误元数据。若改接第三方中文识别服务，应使用服务端保管密钥，并据实际服务更新处理去向说明。
