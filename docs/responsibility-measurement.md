# 责任测量：独立评分与定额分配

按研究者2026年9月16日提供的合作者修订，将原责任主体排序替换为两个连续阶段。每案均作答，四个主体及不同AI条件之间的呈现一致；不再收集另一次强制排名。

1. 独立责任评分：逐一填写0–100整数。0=完全没有责任；100=责任极大。允许同分及全0、全100，不限制总和。四项填写完整后才能进入第二步。
2. 定额责任分配：把全部责任视为100分，在四个主体之间填写0–100整数，合计必须恰好100。实时显示不足／超额。全部四项必填，0与未填区分；禁止自动归一化或按第一步预填。

每案随机排列四个主体，两阶段保持同一顺序。可返回修改独立评分，分配值不自动改变；返回第一步后必须再次进入第二步才能提交。第二案清空全部分值、重新独立作答。刷新保留顺序、阶段和分值。

## 数据字段

测量版本：`independent-and-allocation-2026-09-16-v1`。不改变角色随机分组、AI操纵、两案会话协议或视频素材。

- `responsibilityMeasure`：测量版本。
- `responsibilityOrder`：四主体呈现顺序。
- `responsibilityScores`：judge/court/provider/system各自独立评分。
- `responsibilityAllocation`：同四主体的100分分配。
- `responsibilityAllocationTotal`：提交时合计，必须100。

CSV为每主体、每种测量分别导出一列：`responsibility_score_<id>`与`responsibility_allocation_<id>`，并带版本、顺序和合计。0原样导出；未收集的旧版字段留空。JSON保留完整对象。

旧版已提交排序不变，CSV标记`ranking_legacy`并继续导出原ranking列；不将旧名次转换成分数。旧版未提交进度保留角色、条件、阅读和已填其他量表，责任部分从空白的第一步开始。跨版本两案可能混用不同测量，以每条回答的测量版本识别，分析时不得当作同一测量直接合并。

研究者面板的“法官平均分配分”仅统计新版定额分配。仍为浏览器本地存储的静态原型，本次修改不新增服务器数据收集。

## 验证范围

独立评分范围／同分／全0及全100；分配99、100、101及空值；提交时再次验证；刷新和返回修改；第二案清空；旧记录保留、CSV八个值正确对应；手机布局及既有阅读与音视频流程回归。
